# 마이링크 (my-link) 제품 요구사항 정의서 (PRD)

## 1. 프로젝트 개요
* **프로젝트명:** 마이링크 (my-link)
* **서비스 목적:** 여러 개의 흩어져 있는 소셜 미디어, 포트폴리오, 블로그 등의 링크를 단 하나의 URL(웹페이지)로 통합하여, 누구나 쉽고 직관적으로 공유할 수 있는 링크트리(Linktree) 클론 서비스입니다. 향후 사용자 시나리오 및 와이어프레임 작성의 기준 문서로 활용됩니다.
* **대상 사용자 (Target Audience):**
  * 여러 소셜 플랫폼(유튜브, 인스타그램 등)을 운영하는 인플루언서 및 크리에이터
  * 포트폴리오, 이력서, 깃허브 등을 한 곳에 묶어 어필하고 싶은 구직자 및 프리랜서
  * 매장 위치, 메뉴, 예약 링크 등을 손쉽게 안내하려는 소상공인

---

## 2. 핵심 기능 목록

### 📌 필수 기능 (MVP - Minimum Viable Product)
1. **간편 사용자 인증:** 구글(Google) 계정 전용 소셜 로그인 및 로그아웃
2. **프로필 관리:** 닉네임(`displayname`) 기반의 URL 설정, 프로필 사진 기본 제공 아바타 선택, 소개글 설정 (이미지 직접 업로드 배제)
3. **링크 관리:** 링크 추가/수정/삭제, 구글 API 연동 및 파비콘(Favicon) 자동 렌더링, 링크 노출 토글(On/Off)
4. **퍼블릭 프로필 페이지:** 고유 URL(`domain.com/닉네임`) 제공, 모바일 뷰에 최적화된 심플한 단일 디자인 반응형 UI (테마 배제)
5. **공유 및 바이럴 최적화:** 동적 오픈그래프(OG) 태그 기반 링크 미리보기 썸네일 및 카드 정보 자동 제공

---

## 3. 각 기능의 상세 설명

### 1) 간편 사용자 인증
* **구글 소셜 로그인 전용:** 번거로운 이메일/비밀번호 가입 절차를 일절 생략하고, 오직 **구글(Google) 계정 연동**을 통해서만 가입과 로그인이 이루어집니다. 이를 통해 계정 관리 코스트를 덜고 사용자 이탈률을 최소화합니다.

### 2) 프로필 관리
* **닉네임(`displayname`) 기반 고유 URL:** 복잡한 영문 핸들이나 식별용 아이디(Username) 구조를 따로 두지 않습니다. 사용자가 입력한 **닉네임 자체가 고유 URL 주소(`mylink.com/닉네임`)**가 됩니다. 닉네임 변경 시 접속 주소도 함께 변경되며, 다른 사람이 이미 사용 중인 닉네임은 중복 처리되어 등록이 제한됩니다.
* **프로필 이미지 (기본 아바타 전용):** 파일 업로드에 따른 스토리지 부담을 피하고 관리를 단순화하기 위해, 이미지 직접 업로드 기능은 없앱니다. 대신 서비스 자체적으로 제공하는 **다양한 기본 아바타 목록** 중에서 마음에 드는 것을 택일하는 방식을 취합니다.
* **소개글(Bio):** 방문자에게 어필할 수 있는 여러 줄 입력이 가능한 프로필 소개글(Bio)을 입력하여 화면 최상단에 노출합니다.

### 3) 링크 관리
* **구글 API를 통한 자동 파비콘 렌더링:** 사용자가 이동할 목적지 웹사이트(URL)를 입력하면, 해당 URL의 형태를 파악하여 **구글 파비콘 API(Google Favicon API)**를 호출해 링크 버튼 좌측에 공식 웹사이트 아이콘을 자동으로 띄워줍니다. (아이콘을 직접 업로드할 필요가 없습니다.)
* **노출 및 표시 여부 토글 (On/Off):** 특정 링크를 목록에서 아예 삭제할 필요 없이, 원할 때만 다시 꺼내 쓸 수 있도록 **활성/비활성 스위치**를 모든 개별 링크에 제공합니다.

### 4) 퍼블릭 프로필 페이지
* **모바일 최우선(Mobile-First) 단일 UI:** 스마트폰 환경 비율에 맞춰 완벽히 설계된 단일 디자인 형태의 반응형 UI를 제공합니다. 사용자가 테마를 변경하는 요소는 과감히 제외하며, PC 등 큰 화면 접속 시에도 모바일 화면 비율로 화면 중앙에 일관되게 정렬되어 보여집니다.
* **단축 공유 기능:** 내 페이지 URL 정보(`domain.com/닉네임`)를 클릭 한 번에 클립보드에 복사할 수 있는 '공유 버튼'을 지원합니다.

### 5) 공유 미리보기 및 OG 태그
* **동적 메타 데이터(OG Tag) 렌더링:** 여러 소셜 채널(카카오톡, 카톡 등)에 링크 전달 시 표출되는 빈 껍데기를 방지합니다. 유저의 `displayname`, 선택한 기본 아바타 및 소개글 정보를 바탕으로 **미리보기 카드(OG 썸네일)가 자동으로 깔끔하게 생성**되어 표출되도록 구현합니다.

---

## 4. 데이터베이스(DB) 모델링 주요 지침

* Firestore 등의 **서브 컬렉션(Subcollections) 지원 데이터베이스 구조**를 차용하여 체계적으로 설계합니다.
* **사용자(User) Document:** 상위 컬렉션에서 각 계정에 대한 사용자 문서를 생성 및 관리합니다.
  * 별도의 아이디(알파벳 핸들) 규칙 없이 닉네임 자체를 URL의 기준으로 사용하므로, 모델링 시 고유 식별자 겸 표출 명칭의 역할로 **`displayname`** 필드를 핵심으로 구축하고 중복 방지 로직을 갖춥니다.
* **링크(Links) Subcollection:** 사용자가 하나 이상 생성하게 되는 개별적인 링크 목록들은 상위 사용자 Document 하위의 **별도 서브 컬렉션**으로 저장하여 구조적으로 종속 및 로드되도록 구성합니다.
